API — <heap-diagram> custom element

Renders v12-style heaps from a declarative block list. Load heap-diagram.js on the page (in mdbook, add it to additional-js in book.toml), then write:

<heap-diagram wrap="128">
  alloc 32
  free  64
  alloc 32
  free  32
  alloc 64
  free  32
</heap-diagram>

Attributes: wrap (bytes per row, default 128), start (hex or decimal start address, default 0), title (optional). Block syntax: one alloc <size> or free <size> per line (also ;-separated). Size must be a multiple of 16, min 16. Same hover behavior as v12 — header for the 3-line summary, footer for the boundary-tag reminder.

alloc 32 free 64 alloc 32 free 32 alloc 64 free 32

A second example — single-row alloc-heavy heap with a custom start address:

<heap-diagram wrap="256" start="0x1000">
  alloc 48
  alloc 32
  free  96
  alloc 64
  free  16
</heap-diagram>
alloc 48 alloc 32 free 96 alloc 64 free 16

Per-block flags: ptr (or *) adds a red lollipop at the start of that block's payload; hl (or !) outlines the block in red as "changed by op". Attribute legend adds a key bar.

<heap-diagram wrap="128" legend>
  alloc 32
  alloc 32 ptr hl
  free  32 hl
  alloc 32
</heap-diagram>
alloc 32 alloc 32 ptr hl free 32 hl alloc 32

Attribute pad prepends the CSE 29 leading-pad cell (8 bytes of alignment + magic-number stash) at the heap start. Use pad alone for the default 8 bytes or pad="16" for a custom size. Hover the pad for the explanation.

<heap-diagram wrap="128" pad legend>
  alloc 32
  free  64
  alloc 16
</heap-diagram>
alloc 32 free 64 alloc 16

v12 — refined wording (status + footer)

Status text now 0b0011 (Prev Busy, This Busy) style — no checkmarks, explicit Busy/Free names, 0b binary prefix. Footer reads "marks this free block's length (NN), so it can merge…" with parens around the number.

v11 — header- vs footer-scoped popups, smaller text

Hover the header (dark slab on the left of each block) for the 3-line summary. Hover the footer (right slab of free blocks) for the italic boundary-tag reminder. Payload area no longer triggers anything. Popup text shrunk from 11px to 9px.

v10 — cursor-following terse popup (any block hover)

Same compact 2-row heap with in-header bit strips. Popup is now a 3-line summary that follows the cursor and flips position near edges, so detail stays visible on tall heaps. Total / header word / status — terse and bit-meaning all in one. Powered by embedded JS, so requires <object> or inline embedding (not <img>).

v9 — bit strip back in headers + popover as bit-meaning reminder

Compact h=36 blocks with size on top + 4-bit strip on bottom (visible in every header and footer). Popover repurposed as a reminder of what each bit field means, not just its value.

v8 — compact + hover popovers (bit detail in popover only)

Blocks shrunk to 36px tall. Pointer marker and row-continues text removed. Bit detail moved out of headers into styled hover popovers (works because of <object> embedding).

v7 — compact + two-row test + beefier pointer
